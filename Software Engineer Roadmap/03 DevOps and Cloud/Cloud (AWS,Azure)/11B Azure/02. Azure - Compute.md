## Topics

- Virtual Machine (VM)
- Virtual Machine Scale Sets (VMSS)
- App Service
- Azure Functions
- Azure Kubernetes Service (AKS)
- Azure Container Instances (ACI)
- Azure Durable Functions

---

# Virtual Machine (VM)

- IaaS service to create Windows/Linux virtual servers.
- Full control over OS and applications.
- Used when OS-level customization is required.
- Supports Auto Scaling using VM Scale Sets.
- AWS Equivalent: EC2.
- Example: Hosting a legacy .NET Framework application.
- Interview: Choose VM when you need full control over the server.

---

# Virtual Machine Scale Sets (VMSS)

- Automatically scales multiple Virtual Machines.
- Increases or decreases VMs based on CPU, memory, or demand.
- Improves High Availability and Scalability.
- AWS Equivalent: Auto Scaling Group (ASG).
- Example: E-commerce website during festival sales.

---

# App Service

- PaaS service for hosting Web Apps, APIs, and Background Jobs.
- Azure manages OS, runtime, patching, and scaling.
- Supports .NET, Java, Node.js, Python, PHP.
- Built-in Auto Scaling and Deployment Slots.
- AWS Equivalent: Elastic Beanstalk.
- Example: Host an ASP.NET Core Web API.
- Interview: Preferred for modern web applications because no server management is required.

---

# Azure Functions

- Serverless compute service.
- Executes code only when triggered.
- Automatically scales based on workload.
- Pay only for execution time.
- Supports HTTP, Timer, Queue, Blob, Event triggers.
- AWS Equivalent: AWS Lambda.
- Example: Generate invoices when a file is uploaded.
- Interview: Best for event-driven and short-running tasks.

---

# Azure Kubernetes Service (AKS)

- Managed Kubernetes service.
- Deploys and manages containerized applications.
- Supports Auto Scaling, Load Balancing, and Rolling Updates.
- Azure manages the Kubernetes control plane.
- AWS Equivalent: Amazon EKS.
- Example: Deploy multiple microservices using Docker containers.
- Interview: Preferred for large-scale microservices and container orchestration.

---

# Azure Container Instances (ACI)

- Runs containers without managing servers or Kubernetes.
- Faster and simpler than AKS.
- Suitable for short-lived workloads.
- AWS Equivalent: AWS Fargate (conceptually).
- Example: Run a batch processing container.
---
# Azure Durable Functions  
  
- Extension of Azure Functions.  
- Used for long-running workflows.  
- Maintains state automatically.  
- Supports Function Chaining, Fan-out/Fan-in, Async HTTP APIs and Monitoring.  
- AWS Equivalent: AWS Step Functions + Lambda.  
- Example: Invoice Processing Workflow.  
- Interview: Used when multiple Azure Functions need to work together as a workflow.

---

## Difference

|Service|Use When|
|---|---|
|VM|Need full OS control|
|App Service|Host Web Apps & APIs|
|Azure Functions|Event-driven execution|
|AKS|Large containerized applications|
|ACI|Single container / short-running jobs|

---

## Revision (1 Minute)

- VM = Virtual Server
- VMSS = Auto Scaling VMs
- App Service = Host Web Apps & APIs
- Azure Functions = Serverless
- AKS = Managed Kubernetes
- ACI = Run Containers without Kubernetes

---

### Interview Tip

One of the most common Azure interview questions is:

> **When would you choose VM, App Service, Azure Functions, or AKS?**

If you remember this simple flow, you'll answer confidently:

- **Need full OS control?** → VM
- **Hosting a Web API or website?** → App Service
- **Need event-driven execution?** → Azure Functions
- **Running microservices in containers?** → AKS
- **Need to run a single container quickly?** → ACI
