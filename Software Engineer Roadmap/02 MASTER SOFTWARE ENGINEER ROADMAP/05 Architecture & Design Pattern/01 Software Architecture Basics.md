### Software Architecture

- Software Architecture - High-level structure of a software system.
- Defines components, responsibilities and interactions.

---

### Architecture Pattern

- Architecture Pattern - Reusable solution for organizing software systems.
- Examples - N-Tier, Clean Architecture, Microservices.

---

### Component

- Component - Independent module performing a specific responsibility.

---

### Layer

- Layer - Logical separation of application responsibilities.

---

### Coupling

- Coupling - Degree of dependency between components.
- Goal - Low Coupling.

---

### Cohesion

- Cohesion - Degree to which related responsibilities stay together.
- Goal - High Cohesion.

---

### Separation of Concerns (SoC)

- Separates different responsibilities into independent modules.
- Improves maintainability.

---

### Dependency Inversion Principle (DIP)

- High-level modules should not depend on low-level modules.
- Both depend on abstractions.

---

### Interface

- Defines a contract between components.
- Promotes loose coupling.

---

### Dependency

- Service or object required by another component.

---

### Abstraction

- Hides implementation details.
- Exposes only required functionality.

---

### Scalability

- Ability to handle increasing workload.

---

### Maintainability

- Ease of modifying and extending the application.

---

### Reusability

- Ability to reuse existing components.

---

### Testability

- Ease of unit and integration testing.

---

### Benefits

- Better application structure.
- Easier maintenance.
- Better scalability.
- Improved testability.
- Easier teamwork.
