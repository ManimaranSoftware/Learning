## Topics

- Microsoft Entra ID (Azure AD)
- Managed Identity
- Role-Based Access Control (RBAC)
- Azure Key Vault

---

# Microsoft Entra ID (Azure AD)

- Cloud-based Identity and Access Management (IAM) service.
- Manages Users, Groups and Applications.
- Supports Single Sign-On (SSO) and Multi-Factor Authentication (MFA).
- Used for authentication and authorization.
- AWS Equivalent: AWS IAM (closest).
- Example: Employee logs into multiple applications using one account.
- Interview: Used to manage identities and secure access.

---

# Managed Identity

- Automatically managed identity for Azure resources.
- Eliminates storing usernames and passwords in code.
- Securely accesses Azure services.
- AWS Equivalent: IAM Role.
- Example: Azure Function accesses Key Vault without storing credentials.
- Interview: Recommended way to access Azure resources securely.

---

# Role-Based Access Control (RBAC)

- Controls who can access Azure resources.
- Assigns permissions using Roles.
- Common Roles: Owner, Contributor, Reader.
- AWS Equivalent: IAM Policies & Roles.
- Example: Developer can deploy resources but cannot delete subscriptions.
- Interview: Used for fine-grained access control.

---

# Azure Key Vault

- Securely stores Secrets, Keys and Certificates.
- Prevents hardcoding sensitive information.
- Supports automatic key rotation.
- AWS Equivalent: AWS Secrets Manager.
- Example: Store Database Connection String or API Key.
- Interview: Never store secrets inside application code.

---

## Difference

|Service|Purpose|
|---|---|
|Entra ID|Identity Management|
|Managed Identity|Passwordless Resource Authentication|
|RBAC|Authorization|
|Key Vault|Secret Management|
