### Structural Pattern

- Structural Pattern - Focuses on organizing classes and objects.
- Simplifies relationships between components.

---

### Adapter

- Converts one interface into another compatible interface.
- Allows incompatible classes to work together.

---

### Facade

- Provides a simplified interface to a complex subsystem.
- Reduces complexity for clients.

---

### Decorator

- Adds new behavior to an object dynamically.
- Does not modify the original class.

---

### Composite

- Treats individual objects and groups of objects uniformly.
- Commonly used for tree structures.

---

### Proxy

- Acts as a placeholder or surrogate for another object.
- Controls access to the original object.

---

### Bridge

- Separates abstraction from implementation.
- Allows both to evolve independently.

---

### Flyweight

- Shares common object data to reduce memory usage.
- Useful when creating many similar objects.

---

### Benefits

- Better code organization.
- Reduced coupling.
- Improved flexibility.
- Easier maintenance.
- Better code reuse.
