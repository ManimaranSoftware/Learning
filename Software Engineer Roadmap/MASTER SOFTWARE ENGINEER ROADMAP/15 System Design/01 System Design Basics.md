### System Design

- System Design - Process of designing scalable, reliable and maintainable software systems.

---

### Functional Requirement

- Defines what the system should do.
- Example - User Registration, Login, Payment.

---

### Non-Functional Requirement

- Defines how the system should perform.
- Examples - Scalability, Availability, Performance, Security.

---

### Scalability

- Ability to handle increasing workload by adding resources.

---

### Availability

- Percentage of time a system remains operational.

---

### Reliability

- Ability to consistently perform expected operations.

---

### Fault Tolerance

- System continues operating even when some components fail.

---

### Latency

- Time taken to process a request.

---

### Throughput

- Number of requests processed in a given time.

---

### Bottleneck

- Component limiting overall system performance.

---

### Horizontal Scaling

- Add more servers to handle increased load.

---

### Vertical Scaling

- Increase resources (CPU, RAM) of a single server.

---

### High Availability

- Minimizes downtime using redundancy and failover mechanisms.

---

### Benefits

- Better scalability.
- Improved reliability.
- Easier maintenance.
- Better user experience.

---

- Component whose failure causes the entire system to fail.
- Should be eliminated in system design.
